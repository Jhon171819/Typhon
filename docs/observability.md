# HTTP observability

Typhon can emit JSON request logs, expose a separate Prometheus endpoint
and export traces to an OTLP/HTTP collector. Configure each independently
before starting `http.serve`.

| Setting | Behavior |
| --- | --- |
| `TYPHON_HTTP_JSON_LOGS=1` | JSON lines on stderr with request ID, trace ID, instance ID, route template, method, status, duration and a stable error code. |
| `TYPHON_TRUST_REQUEST_ID=1` | Accepts one proxy-supplied `X-Request-ID` of up to 64 portable ASCII characters. Configure the proxy to overwrite this header and restrict direct access to the app. Other IDs are generated by Typhon. |
| `TYPHON_TENANT_LOG_KEY` | Optional HMAC secret of at least 32 bytes for correlating tenant pseudonyms across replicas. Default uses a fresh per-process key. |
| `TYPHON_METRICS_ADDR=127.0.0.1:9090` | Serves `/metrics` on a dedicated listener. Bind to loopback or an isolated monitoring network. |
| `OTEL_EXPORTER_OTLP_TRACES_ENDPOINT` | OTLP/HTTP collector URL including `/v1/traces`. |
| `OTEL_SERVICE_NAME` | Resource service name, default `typhon`. Each process has its own resource instance ID. |
| `TYPHON_TRACE_SAMPLE_RATIO` | Root trace sampling fraction in `[0,1]`, default `0.1`. Parent sampling decisions are propagated according to the OpenTelemetry parent-based sampler. |

Successful route authentication supplies the identity used to compute
the pseudonym. Logs, metrics and span attributes omit raw tenant and
subject, request body, headers, URLs, SQL text and arguments, Redis
keys and connection strings. Spans include the native operation name
and safe error status. Metrics use route templates, bounded HTTP methods
and native operation names. Unmatched requests share one route label.
Restrict and expire telemetry in your own collector and log sink according
to the service's retention policy.

## Prometheus

The scrape includes Go heap and GC signals, queue and occupied-worker
gauges, active SSE streams, and aggregate PostgreSQL and Redis connection
counts for Engine-owned pools. Shared physical PostgreSQL pools appear
once. Host probes bypass normal request instrumentation.

```promql
sum by (route) (rate(typhon_http_requests_total[5m]))
```

```promql
histogram_quantile(
  0.95,
  sum by (le, route, stage) (rate(typhon_http_stage_duration_seconds_bucket[5m]))
)
```

The stages are `total`, `queue` until a worker was assigned, and `vm`
while the VM handled the request, including native calls. Native driver
histograms report the corresponding operations separately. Use the stage
values and child spans together to locate latency.

## OTLP exporter

The following minimal OpenTelemetry Collector configuration receives HTTP
traces and prints them using its debug exporter.

```yaml
receivers:
  otlp:
    protocols:
      http:
        endpoint: 127.0.0.1:4318
exporters:
  debug:
    verbosity: basic
service:
  pipelines:
    traces:
      receivers: [otlp]
      exporters: [debug]
```

```sh
TYPHON_HTTP_JSON_LOGS=1 TYPHON_METRICS_ADDR=127.0.0.1:9090 \
  OTEL_SERVICE_NAME=typhon-example \
  OTEL_EXPORTER_OTLP_TRACES_ENDPOINT=http://127.0.0.1:4318/v1/traces \
  TYPHON_TRACE_SAMPLE_RATIO=1 typhon run examples/http_router.ty
```

The server extracts the W3C trace context and creates child spans for
PostgreSQL, Redis and outbound HTTP. Outbound HTTP injects the active
W3C trace context. The exporter batches up to 2,048 queued spans
without blocking requests on the collector. Its requests have a
one-second timeout. Use a TLS collector endpoint outside loopback.
[OpenTelemetry Collector configuration](https://opentelemetry.io/docs/collector/configuration/)
